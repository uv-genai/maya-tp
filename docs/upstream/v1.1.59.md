# Upstream v1.1.59 integration

First sequential checkpoint of the upstream v1.1.59–v1.1.65 batch, on
`claude/upstream-v1.1.59-v1.1.65` from `main` `d6b53f8` (tp-v1.1.45). Upstream
tag is `027992cb`. Source integration does not deploy production binaries,
launchers or configs.

## Semantic integration

**Settings aliases are inverted upstream.** The engines and server now read
`MAYA_*`. An older `STRATA_X` is copied to `MAYA_X` only when `MAYA_X` is unset:
C++ `env_aliases()` runs at static initialisation, Python
`tools/maya_names.alias_env` runs on import, and `env_in` stores a config's env
under `MAYA_*`. Fork-only code that read or set `STRATA_*` directly would
silently miss values given as `MAYA_*`, and a runtime `setenv("STRATA_*")` after
start would not reach `MAYA_*` readers. The fork's own reads and writes now use
`MAYA_*`:

- GLM TP2 batching defaults in `generate.cpp` (`GLM_SEQS`, `GLM_GROUP_EXPERTS`,
  `GLM_ROWS_BATCH/ATTN/SMALL`, `GLM_TP_ROWS_EXPERT_MULTI`, `GLM_MULTI_MTP`,
  `GLM_MTP`) and `TP_MTP`, `GLM_MTP_FIXED`, `GLM_CKPTS`;
- `GLM_KDA_GRAPH`, `GLM_RAM_GB`, `GLM_TP_AR_TRACE`, `TP_TEST_WINDOW_RETRY`;
- the DeepSeek TP2 `DS4_SLOT_KEEP` refusal, which `MAYA_DS4_SLOT_KEEP=1` would
  otherwise bypass.

Explicit `MAYA_`-then-`STRATA_` fallback reads (expert source, DS4 restore tail,
gfx11 chunk cap, EXL3 WMMA shape) are kept. Validation harnesses set both names
so older controls still see them. `AGENTS.md` documents the new direction.

**Conflict resolution.** 34 files conflicted, most of them upstream renames
inside code the fork changed or removed. The fork's earlier removals stay
removed: local multi-GPU peer all-reduce and P2P, DeepSeek lent RAM (including
upstream's #884 recovery inside it), CUDA Q8 tensor-core and lane parity, CPU
EXL3 shuffle/W16/split tests, vision expert lending, and gfx942/MI50/AC922
material. Fork-owned CONTRIBUTING/AGENTS text is kept. Numeric VERSION stays
`1.1.45`.

**DeepSeek borrow clear (`f6bf54d1`).** Upstream #884 rewrote the one-GPU
borrow clear to clear a failed device memset's error and retry it, using a
`DS4_TEST_LEND_FAULT` hook that lives in the removed lent-RAM code. As merged,
`maya-ds4` did not compile, and clearing then retrying an uncertain device error
conflicts with the fork's sticky device-error handling. The fork's one-shot
clear is restored; the unused `lent_recover`/`clear_retry` helpers and their CPU
test are removed.

**Installer recommendation fix.** Upstream's new memory-fit recommendation in
`choose_model` referenced the Metal branch the fork removed from that function.
The `NameError` was swallowed, so the recommendation ignored the PC's memory.
Upstream's new `FitRecommendation` test caught it; the call is now
`setup_gpus(a)`. A scope-aware undefined-name scan of all 81 merge-touched Python
files is clean.

**Imported as-is.** Fair-slice pausing of one runner per waiter (#883), refusal
ablation direction catalog entries (paired ablation remains refused before
mutation; the installer still skips direction acquisition for paired configs),
GLM-5.3 (744B) Turbo/route-affinity and memory-fit context (full-model TP2
remains refused before bootstrap), dashboard chat-default separation and the
NVIDIA-only DS4 peer all-reduce selection fix (not reachable on HIP TP2).

**hipBLASLt tuning header (`147d2684`).** Upstream renamed the tuning-table
header to `MAYA_HIPBLASLT_TUNING_V1` in the parser, the tuner and every table,
with no legacy acceptance. The names are not interchangeable: the installed
engines (built before v1.1.59) accept only `STRATA_HIPBLASLT_TUNING_V1` and
silently fall back to hipBLASEx on any other header, and each TP2 rank reads the
tables of its own host's checkout. The parser now accepts both names; committed
tables and `tools/hip/tune_hipblaslt` keep the legacy header so engines of
either age read them. `tests/hipblaslt_tuning_header_test.cpp` (CPU, in the
workflow) checks both headers, rejects other magic and loads every committed
gfx1151 table.

every fixed normal response of the frozen v1.1.58 results token for token
(0 differences), with real MTP/DSpark proposals and ordinary/speculative
