# Upstream v1.1.52 integration

Issue #130 tracks branch `merge/upstream-v1.1.52`, based on validated v51 main
`7f8b78254e39cd43aa9500522e1733371ffabb14`. The upstream tag is
`3c935e411cd6625a9af0f292dd0af52598e866d8`. V51 exact-head, PR and merged-main
CI passed before this branch started. V53 waits for this PR and merged-main CI.

## Semantic review

GLM's FFN graph refactor overlaps the fork's sliced dense FFN path. The merge
retains `ff_compute_dense()` for every dense matrix shape and its ordered TP
all-reduce inside the new FFN body. Active remote TP disables layer graph capture.
The local speculative-window dispatch sites retain `!tp2`, and the existing MTP
wire callbacks remain in the public API. Mirrored fixed-draft MTP, cancellation,
snapshot/reset and sticky transport failures retain their paired control paths.
Upstream local-split window/worker options remain opt-in. The inherited single-host
graph switch retains its fork default-off setting.

Applicable changes include IQ1 CPU row vectorization and parity-gated selection,
F16 dense-to-BF16 conversion, Linux Engram reader sizing, early config validation,
engine-token error handling, model-file ownership and HIP installer fixes. Imported
installer tests now use the fork's existing compiler discovery API and omit the
excluded Metal helper. All other model-selection and HIP_PATH safeguards remain
in place.

The new optional gfx1151 indexer WMMA path is integrated with its component probe.
`DS4_INDEX_TC` remains off by default. New CUDA peer-VRAM transport and compatibility
backend, gfx906-specific paths, Metal references and unrelated discrete-GPU
benchmark material are excluded. Existing remote RDMA reductions and transport
failure guards are retained. Fork README/AGENTS, VERSION and llama.cpp pin are
preserved. Operational docs receive applicable semantic edits.

## Validation

HIP mapping passed. All 695 server tests passed with 11 local skips. All 731 tools
tests passed with 3 local skips after adapting two upstream test mocks. The 58
focused HIP installer tests passed. Release gfx1151 builds passed for `maya`,
`maya-ds4`, `maya-mm3`, the TP verifier, the indexer probe and CPU row probes.

Five CTest cases passed, covering native row exactness, IQ1_S no-pdep and measured
selection, row preparation/fallback policy and native-experts-OFF stub. The GPU
route comparator passed padding, mismatch and first-cause checks. The default-off
indexer probe passed all listed query/window/candidate/scale-edge cases. Masks and
top-512 positions matched, with finite-score differences within the probe's FP32
rounding bound. This component evidence leaves end-to-end quality/performance
with the option enabled as a separate measurement. Paired runs use the default
indexer.

Validation uses the same isolated source/build/runtime paths and host roles as
v50/v51. Both hosts have matching versioned binaries. Controls use
`engines/v1.1.51` and candidates use `engines/v1.1.52`, under the v52 server.
Candidate GLM additionally requests `MAYA_GLM_KDA_GRAPH=1`,
`MAYA_GLM_DSA_FFN_GRAPH=1` and `MAYA_GLM_SPEC_WIN=1` to exercise the TP exclusion
gates. Both builds keep fixed two-draft mirrored MTP. Protected accepted runtime
selection is preserved.

GLM passed actual MTP acceptance, cancellation during a 6,618-token prefill,
healthy follow-up and candidate active peer loss. The original peer-close cause
remained sticky and a later generation request was rejected. XS/S passed real
DSpark proposals, speculation-off/on exact text, paired mutation/restart guards,
healthy follow-up and candidate tokenizer/logit-bias requests. Both models also
read 1,142 fresh prompt tokens across five 256-row chunks and completed a further
64-token answer with DSpark drafts. Every owned validation pair exited.
