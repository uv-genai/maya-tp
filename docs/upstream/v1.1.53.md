## Semantic review

Integrated serving/UI changes, model storage and catalog dependency handling,
EXL3 packing fixes and layout diagnostics, optional prompt memoization and an
agent-shaped API benchmark with its unit tests. The fork's model-management
opt-in default, running-pair mutation guards and disabled paired context-reload
controls remain in place. README, AGENTS, contributor rules and operational
documents receive applicable semantic edits. Numeric VERSION and llama.cpp pin
are preserved.

The DeepSeek GPU-fault backstop detects unusable device state and ends that engine
after the request. Incoming recovery assumed a one-process restart. The fork's
`END` handler marks a TP2 pair down immediately, retains any earlier fatal cause
and rejects later generation. Diagnostics require restarting both ranks. New
regression coverage exercises ordinary and tagged request routing and prior-cause
retention. GPU-fault coverage uses mocked engine output.

GLM's engine and DeepSeek's existing TP2 geometry, 256-row boundaries, queued
reductions and DSpark control retain the v52 implementation. DeepSeek model
changes are limited to the fault backstop and complete cross-file/layout error
tracking. Existing EXL3 helper dependencies are retained.

New Metal, POWER9, Docker, gfx950 and CUDA-only Q8/lane-parity paths are excluded.
The new EXL3 CPU, placement, lending and flow experiments are also deferred for
scoped gfx1151 assessment in [#133](https://github.com/uv-genai/maya-tp/issues/133).
Their source, settings and documentation are excluded together. This merge
preserves tag ancestry while selecting the changes applicable to the fork.

`MAYA_PROMPT_MEMO` and `MAYA_TURN_TRACE` remain off by default. The existing
`maya_names.lookup` implements their STRATA aliases and MAYA precedence. The
prompt memo's `verify` mode compares incremental IDs with full encoding. The
benchmark harness has request/metrics unit coverage. Full agent-load performance
and optional memoization speed remain separate measurements.
