# Upstream v1.1.61 integration

Third sequential checkpoint of the upstream v1.1.59–v1.1.65 batch
([#174](https://github.com/uv-genai/maya-tp/issues/174), epic
[#179](https://github.com/uv-genai/maya-tp/issues/179)). Upstream tag is
`f66a913c`; merge `d6e3bc87` plus the TP2 guard `b3048fff`, following the
validated v1.1.60 checkpoint. No production binary, launcher or config is
changed.

## Semantic integration

**Imported.** DeepSeek's APU prompt-reading kernels (each expert's weights
unpacked once for more rows; sparse attention over all head groups of a token)
and HIP EXL3 decode inlining, both stated by upstream to keep answers; the
per-layer long-prompt cut structure (`Run::ck/cr`, `FeedPlan::cone`,
`plan_cut`) with its opt-in cone; MiniMax one-GPU prompt lookup; DSpark
calibration over chat, code and tool calls.

**DeepSeek's eager DSpark round stays.** The fork never imported upstream's
lazy drafter (#622): `Model::draft` has no lazy parameters and `round()` drafts
every row before choosing the cut. v1.1.61's trusted prompt lookup is built on
the lazy round, so it is not wired into `round()`; its bookkeeping and the
`lookup_trust` request key compile but cannot fire. DeepSeek TP2 negotiates
lookup separately (`MAYA_DS4_TP2_LOOKUP`, launcher default 0, batched mode
requires 0). The run plan keeps the fork's single `snap_pos` and
`plan_chunks` without restore marks.

**Fast prompt reading refused for TP2 (`b3048fff`).** Upstream's opt-in fast
prompt reading (`fast_prefill` → `DS4_YOCO_CONE=1`) plans each layer's first
prompt row from the process's own environment. On a remote TP2 rank every layer
is local, so the cone would apply, but only the rank-0 server sets it and the
pair identity does not carry it: the ranks could plan different rows for a
chunk. It is refused for DeepSeek TP2 in the engine before bootstrap, at server
start and on the Models page; single-host DeepSeek keeps the switch. Boundary
tests and a pre-bootstrap engine probe cover it.

Conflicts in `maya.py` (MiniMax lookup default plus the fork's `--vision`
handling), `exl3.cu` (upstream's inlining with the fork's `J.nc`) and the
changelog were merged directly. Numeric VERSION stays `1.1.45`.

## Flash GPU checkpoint

All six GLM Flash Maya-S / DeepSeek Flash XS/S default1 and batch2 cases match
the frozen v1.1.60 results token for token (0 differences), with real
MTP/DSpark proposals and ordinary/speculative equality inside each case. GLM
false-valued `NO_*` flags still reach bulk prefill and MTP; the Chinese
whole-head fallback, batched cancellation/refill/reuse and first-fatal fanout
(0.697 s GLM / 0.886 s XS) pass. The new DeepSeek prompt-reading kernels keep
TP2 answers identical.
