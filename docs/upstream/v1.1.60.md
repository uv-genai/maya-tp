# Upstream v1.1.60 integration

Second sequential checkpoint of the upstream v1.1.59–v1.1.65 batch
([#173](https://github.com/uv-genai/maya-tp/issues/173), epic
[#179](https://github.com/uv-genai/maya-tp/issues/179)). Upstream tag is
`8b0a449c`; merge `aab6f369` on `claude/upstream-v1.1.59-v1.1.65`, following the
validated v1.1.59 checkpoint (`147d2684` engines). No production binary,
launcher or config is changed.

## Semantic integration

**GLM routing ring on HIP.** GLM's host-mapped routing ring is now sized from
the model on HIP: GLM-5.3-Flash uses 64 entries of 4096 floats instead of 256
entries of 8192 (1 MB instead of 8.4 MB). Upstream measured this as restoring
v1.1.56's single-APU drafting decode. Every routing-ring access in the fork goes
through `ring_entry` with the ring's recorded shape; the remaining fixed-size
rings (`pfce_seq_h`, the indexer key ring, DeepSeek attention windows) are
upstream's own and unchanged. The engine counts ring laps but does not report
them; the batched GLM outputs below are identical.

**Imported as-is.** GLM-5.3 (744B) DFlash2 drafting opt-in and its graph/capture
rules, GLM-5.3 setup context recommendation (4 GB more engine room), and
turboderp's DeepSeek EXL3 2.25 bpw setup entry. Full-model TP2 stays refused
before bootstrap; no 744B model or new quant is downloaded or run.

**Documentation.** Conflicts were documentation only. README stays fork-owned
(upstream's NVIDIA community speed tables are not imported); MODELS/SETUP keep
the fork's wording and add the EXL3 2.25 bpw entry; translated READMEs stay
removed. Numeric VERSION stays `1.1.45`.
