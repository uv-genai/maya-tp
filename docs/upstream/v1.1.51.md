## Semantic review

Retained applicable server/UI fixes, numeric-string DeepSeek effort levels,
installer preservation of host/auth/CORS/MCP settings with the fork's HIP config
suffix, savings-ledger placement, opt-in CPU row startup preparation and a
configurable RAM margin with the existing 8 GiB default. New CPU policy and
native-experts-OFF stub checks run after the required ordered CI gates.

The DeepSeek conflict resolution retains every remote TP2 attach, step and
first-failure entry point. The new local-group room-based reload explicitly
excludes remote TP2 ranks, whose checked manifests define their split. Local-group
share and host-free options remain scoped to those in-process groups. Borrowed
MXFP4 slots can prefetch their reload when sufficient RAM is available. Accepted
paired runs keep the explicit 256-row chunk and matching rank configs.

GLM mirrored resets remain ordered before local reset. The new checkpoint lambda
returns zero for RDMA TP2, preserving the constraint that checkpoint operations
have no mirrored protocol. Existing snapshot reuse and fixed two-draft MTP remain
paired. The watchdog completion heartbeat and stale cancellation-error reset are
integrated.

Fork README/AGENTS, numeric VERSION and the llama.cpp pin are preserved.
Upstream translations, Metal and previously deferred ReBAR/local transport and
vision-control blocks are excluded. Operational documentation is merged
semantically. Issue #128 corrects an existing optional Textual readiness test
teardown race, reproduced on v50, by using its normal stop confirmation before
leaving the test context. Production terminal UI code is unchanged.
